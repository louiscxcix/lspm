# 독립 시간별 생산실적 앱

작성일: 2026-10-15 (America/Mexico_City)
상태: 대화에서 설계 승인 완료. 이 문서 검토 후 구현 계획 작성.

## 1. 목적과 경계

현장 작업자가 시간별 생산량을 입력하고, 관리자가 목표를 설정하며,
확정 Excel과 업로드 데이터를 동일한 내용으로 만드는 별도 웹앱이다.
기존 PM 앱과 주소, 실행 서비스, DB, 관리자 인증, 작업자 접근 권한을 공유하지 않는다.
소스는 독립 앱 디렉터리에 두며, 기존 PM 앱 코드를 작업 디렉터리로 사용하지 않는다.
기존 PM 앱의 색상, 글꼴, 버튼, 표, 카드, 여백과 차트 표현은 가능한 범위에서 재사용한다.

별도 앱과 비공개 Upload DB를 두고 PM이 확정 자료를 가져오는 구조를 선택했다.
PM DB를 직접 공유하는 방식은 접근 권한 분리 요구에 맞지 않아 제외한다.
Excel 수동 가져오기만 제공하는 방식은 자동 연동 요구를 충족하지 않아 제외한다.

## 2. 접근과 표시

- 개인별 계정, 가입, 작업자 로그인 화면은 만들지 않는다.
- 발급된 입력 링크를 가진 작업자는 해당 앱의 공유된 작성본을 조회하고 실적을 입력한다.
  입력 링크는 작업자용 접근 수단이며, 이를 아는 사람은 입력할 수 있다.
- 관리자 비밀번호는 이 앱 전용 하나만 둔다. 사용자가 지정한 초기 값은 배포 환경의
  비밀 설정에 넣고 저장소, 문서, 화면 코드, 브라우저 응답에는 넣지 않는다.
- 관리자 비밀번호 검증과 목표 변경 권한 검사는 서버에서 수행한다.
  로그인 시도 제한과 세션 만료를 두고 PM 관리자 자격 증명은 사용하지 않는다.
- 목표 입력과 변경은 관리자만 가능하다. 확정 전 실적과 사유는 관리자와 작업자 모두 수정한다.
- 관리자가 입력한 목표, 실적, 변경 내용은 작업자에게도 자동 반영한다.
  작업자 변경 내용도 관리자가 같은 작성본에서 확인한다.
- 확정 Excel 제작과 확정본 업로드는 작성본에 접근 가능한 작업자 또는 관리자가 실행할 수 있다.
- 업로드 확정 자료 및 연동용 인증 정보는 공개 웹 자산이나 공개 DB로 내보내지 않는다.

## 3. 생산일과 입력

- 선택 기준: 생산일, 라인, 모델. 같은 모델이 다른 라인에 있어도 기록을 합치지 않는다.
- 생산일은 America/Mexico_City의 07:00부터 다음 날 07:00 직전까지이며 24개 시간 구간이다.
  자정 이후 07:00 이전 구간도 이전 생산일에 속한다. 화면과 Excel에는 실제 구간 날짜도 표시한다.
- 모델의 표기 이름과 별개로 안정된 모델 코드를 저장한다. 라인에도 안정된 코드를 사용한다.
- 관리자는 시간당 목표를 24구간 또는 선택 구간에 일괄 적용하고 각 구간을 개별 조정한다.
  일괄 적용이 기존 목표를 바꿀 때 범위를 명시한다. 비가동 구간의 목표 0도 허용한다.
- 실적은 해당 구간에 생산한 수량이다. 누적 카운터나 공정별 WIP가 아니다.
- 목표와 실적은 0 이상의 정수 또는 미입력이다. 미입력을 0으로 바꾸지 않는다.
- 미달 사유는 선택 입력이다. 사유 없이도 입력, Excel 제작, 업로드가 가능하다.
- 입력값 단위는 기본 pcs로 표시하고, 다른 단위의 모델은 명시적으로 분리한다.
- 합계, 비교 가능한 구간의 달성률, 부족 수량과 시간별 목표/실적 차트를 제공한다.
  목표 0 또는 미입력일 때 달성률은 표시하지 않는다.
  미입력 구간 수와 집계 범위를 표시해 부분 실적을 완전한 하루 실적으로 오인하지 않게 한다.

## 4. 작성본, Excel 확정, DB 업로드 분리

화면에는 상태를 `작성 중`, `Excel 확정 / 업로드 전`, `업로드 완료`로 구분한다.

1. 작성 중: 앱 전용 임시 저장 영역의 현재 값만 갱신한다. 이전 값이나 수정 이력은 보관하지 않는다.
   임시 저장은 기기 간 공유를 위한 것이며 PM과 연결되는 Upload DB에는 전달하지 않는다.
2. Excel 제작: 서버가 현재 작성본을 검증하고 동일 값의 보고서를 생성한 뒤 해당 작성본을 잠근다.
   생성 도중 내용이 바뀌었으면 확정하지 않고 최신 내용 확인을 요청한다.
   실제 보고서 생성 실패 시 작성 상태를 유지한다.
3. 확정 후: 관리자와 작업자 모두 수량, 목표, 사유를 변경하거나 잠금을 해제할 수 없다.
   다운로드가 끊겼어도 같은 확정본으로 Excel을 다시 다운로드할 수 있다.
   재다운로드는 새 확정 자료를 만들지 않는다.
4. DB 업로드: 별도 버튼으로 확정본만 Upload DB에 추가한다. Excel 제작만으로 업로드하지 않는다.
   생성된 Excel과 업로드 자료는 동일한 reportId 및 내용 해시로 같은 확정 내용을 가리킨다.
5. Upload DB의 확정 자료는 변경하거나 삭제하는 기능을 제공하지 않는다.
   중복 클릭, 네트워크 재시도는 같은 reportId로 처리하고 중복 자료를 만들지 않는다.
   같은 생산일, 라인, 모델, 단위에 다른 확정본을 새로 만들어 기존 수량을 우회 수정할 수 없다.
6. 업로드 실패 시 확정 내용은 유지하고 업로드 전 상태에서 재시도한다.
   업로드 성공과 PM 수신 성공은 별도로 표시한다.

확정 후 정정, 승인 단계, 버전별 기록, 이전 값 복구는 이번 범위에서 제외한다.
화면에는 Excel 제작 전에 이후 내용을 수정할 수 없다는 확인 문구를 표시한다.

## 5. Excel 보고서

- 실제 .xlsx 파일로 제공한다. 별도의 DB 업로드 없이 다운로드할 수 있다.
- 생산일, 라인, 모델명과 코드, 단위, 확정 시각을 표시한다.
- 24개 시간별 목표, 실적, 차이, 달성률, 선택 사유를 표로 제공한다.
- 일일 계획 목표, 입력된 실적, 비교 가능한 구간의 달성률, 미입력 상태를 구별한다.
- 시간별 목표/실적 비교 그래프와 보고용 합계 영역을 포함한다.
- 실제 0은 숫자 0, 미입력은 빈칸 또는 미입력 표시로 구별한다.
- 긴 사유의 줄바꿈, 인쇄 범위, 반복 헤더와 읽기 쉬운 열 너비를 설정한다.
- 사용자 입력은 문자열로 처리해 Excel 수식으로 실행되지 않게 한다.

## 6. Upload DB와 PM 연동

- 앱 DB와 Upload DB는 PM과 독립된 앱 전용 저장소에 둔다.
  임시 작성본과 불변 업로드 자료는 별도 저장 영역과 권한으로 구분한다.
- 업로드 자료에는 스키마 버전, 앱 식별자, reportId, 생산일, 시간대, 라인 코드,
  모델 코드, 단위, 24구간의 시작/종료 시각, 목표, 실적, 사유, 확정/업로드 시각과
  내용 해시를 포함한다. 실제 저장된 자료만 업로드 완료로 표시한다.
- PM 연동기는 별도의 서버용 읽기 자격 증명으로 Upload DB의 확정 자료만 가져온다.
  작업자 링크나 앱 관리자 비밀번호로 PM에 접근할 수 없다.
- PM의 기존 모델/라인 ID는 확인된 코드 매핑으로 연결한다.
  이름이 비슷하다는 이유로 생성, 병합, 공정 경로 배정하지 않는다.
  미매핑 자료는 수신 보류로 남기고 원문을 유지한다.
- PM에는 시간별 모델 생산실적 자료로 저장한다. 기존 WIP, 공정 구조, 설비 연결,
  재고, History 원문을 덮어쓰지 않는다. 모델 전체 수량을 모든 공정에 복제하지 않는다.
- 앱 식별자와 reportId를 PM 수신 키로 사용하며 저장 완료 뒤에만 처리 위치를 갱신한다.
  재시도와 중단 후 재개가 가능하고 PM 수신 자료도 동일 업로드를 중복 합산하지 않는다.
- PM이 꺼지거나 연동이 실패해도 생산 앱의 입력, Excel 제작과 Upload DB 저장은 동작한다.
  PM 연동이 재개되면 미수신 자료를 처리한다. 매핑과 수신 상태는 확정 수량과 별도 관리한다.
- GitHub 연동은 코드 및 배포 구성 관리용이다. 비밀번호, 작업자 링크, 연동 키,
  실적 데이터, 생성 Excel은 커밋하지 않는다. 이 설계 승인만으로 저장소 공개나 비용 발생을 승인하지 않는다.

## 7. 구현 및 완료 검증

기존 PM 저장소에는 이 설계 문서만 추가한다. 다른 대화에서 수정 중인 PM 앱 파일,
운영 DB, 접근 설정과 배포를 현재 단계에서 변경하지 않는다.
독립 앱을 먼저 구현하고, 격리된 시험 자료로 PM 수신기를 검증한 후 연동한다.
실제 배포 대상과 필요한 서비스 권한은 구현 계획에서 기존 사용 가능 환경을 확인해 정한다.

필수 검증:

- 작업자 기기에서 관리자 목표 및 실적 변경이 자동으로 보인다.
- 관리자 인증 없이 목표 변경이 서버에서 거절된다. PM 자격 증명으로 앱 관리자 권한을 얻지 못한다.
- 자정과 07:00 경계, 같은 모델의 다른 라인, 실제 0과 미입력, 목표 0이 올바르게 처리된다.
- 확정 전 자유 수정에 이전 값이 남지 않고, 동시 저장 충돌을 조용히 덮어쓰지 않는다.
- Excel 실패 시 잠기지 않으며 확정 후에는 API 직접 호출로도 수정할 수 없다.
- .xlsx를 다시 열어 표 값, 그래프, 합계, 인쇄 범위와 사유를 확인한다.
- Excel과 업로드의 내용이 같고 중복 전송, 실패 재시도, 확정 후 변조가 처리된다.
- PM은 확정 자료만 수신하고 중복 집계, 임의 모델 매핑, 기존 WIP 변경을 하지 않는다.
- PM 미가동 중에도 앱이 동작하고 재개 시 누락분만 수신한다.
- 관리자 비밀, PM 연동 키 및 확정 자료가 브라우저 공개 코드나 GitHub에 노출되지 않는다.
